# Qalqan — щит от мошенников внутри приложения банка

[![CI](https://github.com/adiletpn/Qaqpan/actions/workflows/ci.yml/badge.svg)](https://github.com/adiletpn/Qaqpan/actions/workflows/ci.yml)

Прототип для **ITU HACKATHON-2026 · FINTECH CASE** (кейсодатель — Банк ЦентрКредит).

Любое мошенничество проходит четыре шага: **написали → позвонили → уговорили перевести → получили деньги**.
Qalqan ставит защиту на каждый шаг, и слои передают сигнал друг другу: то, что пропустил один, ловит следующий.

| Шаг мошенника | Слой Qalqan | Как работает |
|---|---|---|
| 1. Написали | **Проверка сообщений** | Текст, ссылка или скриншот → вердикт и причины на русском или казахском. Быстрые правила по схемам Казахстана + Claude (распознавание изображений) поверх них |
| 2. Позвонили | **«Банк мне звонит?»** | Одна кнопка во время звонка. Сверка с журналом исходящих звонков банка: «да, это сотрудник Асем, отдел кредитования» или «банк вам НЕ звонит» |
| 3. Уговорили перевести | **Умный перевод** | Прозрачный риск-скор (звонок, новый получатель, доля баланса, жалобы на счёт, вставка реквизитов, переключение приложений) → предупреждение / пауза и вопросы / задержка |
| | **Семейный щит** | Крупный подозрительный перевод ждёт подтверждения доверенного лица — даже если мошенник подсказал ответы на вопросы. Нет ответа 15 минут → звонит сотрудник банка, а не вечная блокировка |
| 4. Получили деньги | **Сеть защиты** | Жалоба одного клиента помечает счёт → все, кто пытается туда перевести, получают предупреждение |
| Если всё же обманули | **Помощь пострадавшему** | Что делать прямо сейчас + готовое заявление в полицию |
| Новые схемы | **Радар схем** | Карточки новых схем из новостей Казахстана со ссылками на источники |

## Демо

```bash
make setup     # Python 3.12 venv + зависимости + npm install
make demo      # сборка фронта и сервер на http://localhost:8000 (ИИ только из кэша)
```

| Страница | Для чего |
|---|---|
| `/stage` | Проектор: три телефона (Айгерим, её сын Ержан, Мадина), полоса 4 шагов, счётчик остановленных попыток |
| `/director` | Пульт ведущего. Клавиши `1`–`5` — сценарий, `B` — настоящий звонок банка, `R` — сброс (работают и на `/stage`) |
| `/phone/aigerim` | Приложение на весь экран — открыть на настоящем телефоне |

Сценарий по секундам и ответы на вопросы жюри: [docs/DEMO_SCENARIO.md](docs/DEMO_SCENARIO.md).

### ИИ-слой

Без ключа всё работает на правилах и шаблонах. С ключом проверка сообщений и заявление используют Claude
(`claude-opus-5-5`, структурированный ответ, кэш в `data/llm_cache/`):

```bash
cp .env.example .env   # или export ANTHROPIC_API_KEY=...
make warm              # ответы ИИ для всех демо-скриншотов → data/llm_cache/ (закоммитить)
make api               # живые вызовы разрешены
```

## Что настоящее, а что симуляция

| Настоящее | Симуляция (в банке — интеграция) |
|---|---|
| Проверка сообщений (правила + Claude), скриншоты, RU/KK | Журнал исходящих звонков банка |
| Риск-скор перевода и причины | Факт звонка (в приложении банка: `CXCallObserver` / `AudioManager.getMode()`) |
| Вопросы, семейный щит с таймаутом | Процессинг переводов и балансы |
| Жалобы и сеть защиты | База Антифрод-центра (один счёт в демо помечен как «в базе») |
| Вставка реквизитов и уход из приложения (`paste`, `visibilitychange`) | Входящие SMS и звонки (запускаются с пульта) |

Принципы: в платёжном потоке клиенту показываются только утверждённые тексты (`api/texts.py`), без свободной
генерации; клиенту не раскрываются операции чужого счёта; казахские тексты требуют вычитки носителем.

## Качество

- CI (GitHub Actions): тесты API, линтер и сборка фронта на каждый push.
- `make test` — 37 тестов: «золотой путь» всего демо через API + крайние случаи (обычный перевод проходит, настоящий звонок банка подтверждается, таймаут семьи не блокирует навсегда).
- `make e2e` — прогон демо в настоящем Chrome кликами со скриншотами.
- `make eval` → [docs/METRICS.md](docs/METRICS.md): правила ловят **86%** мошеннических сообщений при **1** ложной тревоге из 18 на нашем наборе. Набор маленький и в основном сконструирован — это проверка поведения, а не боевая точность.

## Архитектура

```
web/ (React + Vite + TS + Tailwind)  ──poll 1s──▶  api/ (FastAPI, состояние в памяти)
  phone/  приложение банка                          main.py     эндпоинты 4 слоёв, пульт, лента событий
  pages/  Stage, Director                           risk.py     скоринг перевода с кодами причин
                                                    msgcheck.py правила + Claude vision
                                                    llm.py      кэш → живой вызов → фолбэк
```

Один процесс раздаёт и API, и собранный фронт. Запускать **с одним воркером**: состояние демо хранится в памяти.
