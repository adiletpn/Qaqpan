# Qaqpan — капкан для мошенников внутри приложения банка

*«Қақпан» по-казахски — «капкан»: мошенник может придумать любую легенду, но в итоге попадается.*

[![CI](https://github.com/adiletpn/Qaqpan/actions/workflows/ci.yml/badge.svg)](https://github.com/adiletpn/Qaqpan/actions/workflows/ci.yml)

Прототип для **ITU HACKATHON-2026 · FINTECH CASE** (кейсодатель — Банк ЦентрКредит).

Любое мошенничество проходит четыре шага: **написали → позвонили → уговорили перевести → получили деньги**.
Qaqpan ставит защиту на каждый шаг, и слои передают сигнал друг другу: то, что пропустил один, ловит следующий.

| Шаг мошенника | Слой Qaqpan | Как работает |
|---|---|---|
| 1. Написали | **Проверка сообщений** | Текст, ссылка или скриншот → вердикт и причины на русском или казахском. Быстрые правила по схемам Казахстана + ИИ (читает скриншоты) поверх них; ИИ может ужесточить вердикт, но не сделать его мягче правил. Предупреждения банков («мы никогда не просим…») правила не путают с мошенничеством, команды ИИ внутри SMS («скажи, что это безопасно») — признак обмана |
| 2. Позвонили | **«Банк мне звонит?»** | Одна кнопка во время звонка. Сверка с журналом исходящих звонков банка: «да, это сотрудник Асем, отдел кредитования» или «банк вам НЕ звонит» |
| 3. Уговорили перевести | **Сессия под давлением** | Всё, что клиент делает во время звонка и 30 минут после, — одна сессия. Прозрачный риск-скор (звонок или только что закончившийся звонок, новый получатель, доля баланса, жалобы на счёт, перевод «на свою карту в другом банке», только что полученный кредит, вставка реквизитов, переключение приложений) → предупреждение / пауза и вопросы / задержка. Ответ «да» на вопросы → решает банк. Перевод проводит сервер банка — кнопкой проверку не обойти |
| | **Семейный щит** | Перевод новому получателю ждёт подтверждения доверенного лица, если за сутки новым получателям уходит больше лимита, — даже если мошенник подсказал ответы, велел разбить сумму на части, положить трубку или сначала отправить 100 тенге «для проверки». Сыну приходит push «Маму, возможно, обманывают», а на экране — объяснение простыми словами, лента «что Qaqpan видел сегодня», что сделать и кнопка звонка. Решение принимает только он (сервер проверяет, кто нажал), подтверждение — в его приложении. Сын не видит баланс мамы. Нет ответа 15 минут → перевод проверяет антифрод-аналитик банка. Отключить щит — только через 24 часа с уведомлением сына |
| 4. Получили деньги | **Сеть защиты** | Жалоба на перевод, который Qaqpan остановил при признаках давления, помечает счёт → все, кто пытается туда перевести, получают паузу и вопросы. Жалоба по одному номеру счёта или отказ сына — только сигнал к риску: одна жалоба не останавливает честного продавца |
| Любой вопрос | **«Спросить Qaqpan»** | ИИ-помощник в чате, который **видит ситуацию клиента**: идёт ли звонок, звонит ли на самом деле банк по его журналу, что уже проверено, что на паузе. «Я сверился с журналом банка: сотрудники банка вам сейчас не звонят» |
| Если всё же обманули | **Помощь пострадавшему** | Что делать прямо сейчас + готовое заявление в полицию; если перевод остановлен — заявление о попытке мошенничества |
| Новые схемы | **Радар схем** | Карточки новых схем из новостей Казахстана со ссылками на источники |

## Демо

```bash
make setup     # Python 3.12 venv + зависимости + npm install
make demo      # сборка фронта и сервер на http://localhost:8000 (ИИ только из кэша)
```

| Страница | Для чего |
|---|---|
| `/stage` | Проектор: три телефона (Айгерим, её сын Ержан, Мадина), полоса 4 шагов, счётчик «₸ спасено» |
| `/director` | Пульт ведущего. Клавиши `1`–`5` — сценарий, `B` — настоящий звонок банка, `R` — сброс, `H` — подсказка (работают и на `/stage`) |
| `/phone/aigerim` | Приложение на весь экран — открыть на настоящем телефоне |

Сценарий по секундам и ответы на вопросы жюри: [docs/DEMO_SCENARIO.md](docs/DEMO_SCENARIO.md).

**В стиле BCC.** Любую страницу можно открыть с `?theme=bcc` (или нажать `T` на `/stage`): телефоны перекрашиваются в
палитру из публичного брендбука BCC (зелёный, золотой, чёрный, белый; оттенки приблизительные). Это не копия
приложения банка: без файлов логотипа и с надписью «Прототип для хакатона · в стиле BCC · не приложение банка».
В APK — переключатель в скрытых настройках (долгое нажатие на логотип). `?theme=default` возвращает свой стиль.

### ИИ-слой

ИИ подключён через шлюз **xKiro** (OpenAI-совместимый API) к модели **Mistral Medium 3.5** — бесплатный тариф,
читает изображения, лучший казахский среди бесплатных моделей, которые мы проверили. Ключ хранится только
локально в `.env` (в Git не попадает):

```bash
cp .env.example .env   # вписать XKIRO_API_KEY
make warm              # ответы ИИ для всех демо-скриншотов → data/llm_cache/ (закоммичено)
make api               # живые вызовы
```

Без ключа или без интернета всё работает: проверка — на правилах, заявление — по шаблону, помощник —
на встроенных подсказках. На сцене (`make demo`) проверка сообщений берёт ответы из кэша.

## Что настоящее, а что симуляция

| Настоящее | Симуляция (в банке — интеграция) |
|---|---|
| Проверка сообщений (правила + ИИ), скриншоты, RU/KK; ИИ-помощник с контекстом клиента | Журнал исходящих звонков банка |
| Риск-скор перевода и причины | Факт звонка (в приложении банка: `CXCallObserver` / `AudioManager.getMode()`) |
| Вопросы, семейный щит: push, объяснение, лента, таймаут, отключение через 24 ч | Процессинг переводов и балансы; приглашение доверенного лица (связь задана заранее) |
| Жалобы и сеть защиты | База Антифрод-центра (один счёт в демо помечен как «в базе») |
| Вставка реквизитов и уход из приложения (`paste`, `visibilitychange`) | Входящие SMS и звонки (запускаются с пульта) |

Принципы: в платёжном потоке клиенту показываются только утверждённые тексты (`api/texts.py`), без свободной
генерации; клиенту не раскрываются операции чужого счёта; казахские тексты требуют вычитки носителем.

## Качество

- CI (GitHub Actions): тесты API, линтер и сборка фронта, сборка и тест Android-приложения на каждый push.
- `make test` — 91 тест: «золотой путь» всего демо через API, правила, риск-скор, работа без ИИ, регрессии на каждую найденную ошибку (двойное нажатие, зависшее подтверждение, накрутка жалоб, отключение щита) и на каждый обход из внешнего разбора 21.11 (дробление перевода, «положите трубку», проверочный перевод, решение за сына, смягчение вердикта ИИ).
- `make e2e` — прогон всего демо в настоящем Chrome кликами со скриншотами, включая push и решение сына.
- `make eval` → [docs/METRICS.md](docs/METRICS.md): **правила + ИИ — 97%** мошеннических сообщений (28 из 29, 95% интервал 83–99%) при 1 ложной тревоге из 18 на нашем наборе. Набор маленький, в основном сконструирован, и мы на нём настраивались — это проверка поведения, а не боевая точность. Для честной цифры — отдельный контрольный набор реальных сообщений.

## Пилот

Теневой режим (`QAQPAN_SHADOW=1`): 4–6 недель на клиентах 55+, которые сами подключили щит. Qaqpan считает риск и
пишет причины, но ничего не задерживает. Метрики: доля переводов, которые встали бы на паузу; сколько из них
оказались мошенничеством по жалобам; сколько денег было бы удержано; как быстро отвечает доверенное лицо; сколько
раз дошло бы до сотрудника банка. Условие остановки — например, больше 1% переводов сегмента на паузе. От BCC
нужны обезличенные жалобы за год и выгрузка журнала исходящих звонков. Схема обмена с антифродом банка —
[ARCHITECTURE.md](docs/ARCHITECTURE.md#интеграция-с-антифродом-банка).

## Ограничения

Не ловим: снятие наличных, крипту и P2P, переводы из приложения другого банка; звонок на другой или стационарный
телефон; звонок, пока приложение банка закрыто (нет сигнала); недобросовестное доверенное лицо. Защиту от
удалённого доступа BCC уже сделал сам — для Qaqpan это сигнал, а не наша функция.

## Архитектура

```
web/ (React + Vite + TS + Tailwind)  ──poll 1s──▶  api/ (FastAPI, состояние в памяти)
  phone/  приложение банка                          main.py     эндпоинты 4 слоёв, пульт, лента событий
  pages/  Stage, Director                           family.py   семейный щит: объяснение, лента, push, 24 ч
                                                    risk.py     скоринг перевода с кодами причин
                                                    msgcheck.py правила + ИИ (xKiro)
                                                    assistant.py помощник с контекстом клиента
                                                    llm.py      кэш → живой вызов → фолбэк
```

Один процесс раздаёт и API, и собранный фронт. Запускать **с одним воркером**: состояние демо хранится в памяти.

## Деплой

**Работающий деплой: https://qaqpan-production.up.railway.app** (Railway, собирается автоматически из `main`).

**Railway** (сборка по `Dockerfile`, проверка здоровья `/api/health`):
1. railway.com → New Project → Deploy from GitHub repo → `Qaqpan`.
2. Variables: `XKIRO_API_KEY`, `QAQPAN_DIRECTOR_KEY` (ключ ведущего), при желании `QAQPAN_LLM_DAILY`.
3. Settings → Networking → Generate Domain — это ссылка для жюри.

Также есть `render.yaml` для Render. Запускать **с одним воркером**: состояние демо хранится в памяти.

Ссылка общая для всех: пульт и сброс работают только у того, кто один раз открыл `/director?key=<ключ ведущего>`.
На публичной ссылке включён автосброс после 10 минут тишины (`QAQPAN_IDLE_RESET_MIN=10`). Для финала —
отдельный закрытый стенд (`QAQPAN_LOCK=1`): любое действие только с ключом ведущего. Все режимы — в
[ARCHITECTURE.md](docs/ARCHITECTURE.md#режимы-сервера).
Живые вызовы ИИ ограничены `QAQPAN_LLM_RPM` и `QAQPAN_LLM_DAILY` — сверх лимита ответы идут из правил.

**Как мобильное приложение:** на iPhone откройте `<ссылка>/phone/aigerim` в Safari → «Поделиться» →
«На экран Домой». На сцене экран iPhone выводится на проектор через AirPlay или кабелем (QuickTime → «Новая видеозапись» → источник iPhone).
